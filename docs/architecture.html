Signal chain (one audio frame, end to end)

1. Capture
UNPROCESSED @ 48 kHz
960 int16 samples / 20 ms, ring-buffered on phone
2. Frame
30 B header + PCM + CRC-32C
CRC polynomial 0x1EDC6F41 (Castagnoli, iSCSI test vector)
3. Stream
WebSocket over Wi-Fi Direct
Office Kit bridge, per-packet size cap, rate limit
4. Align
Chirp handshake
17.5-22 kHz PRBS sweep, sub-sample cross-correlation
5. Localise
TDOA → radar
GCC-PHAT per pair, non-linear least-squares 2D fix
6. Beamform
D&S or MVDR
Phase-shift + average, or covariance + weights
7. Transcribe
Indic ASR (NPU)
QNN-exported model, offline, on phone A
8. Render
Radar + transcript
Text-based radar + live transcript, screen-mirrored

Fallback ladder

Each rung degrades gracefully; the demo never blanks. Trigger order: 

  3-phone live beamform   →   2-phone array   →   single-phone enhance (NS+AGC-off)
  Wi-Fi Direct stream  →   chunked file sync (batch reprocess)  →   on-phone-only mode
  Ultrasonic sync     →   cable-ping calibration               →   pre-timestamped exchange

The shruti_array.fallback module owns the laptop-side "am I in fallback mode?" logic and the batch-file ingest path. python -m shruti_array.fallback ingest --corpus <dir> --out <wav> runs the Tier-0 batch beamform (D&S or MVDR).

What runs where

LAPTOP  (the array processor, the load-bearing use of Office Kit)
  protocol · ingest (WebSocket + /metrics) · sync (chirp xcorr) · TDOA (GCC-PHAT)
  beamform (D&S, MVDR) · tracker · radar · render (text + judge-facing overlays)
  fallback ladder · regression harness · synthetic corpus · microbenchmark

PHONES  (one master + two elements, foreground services)
  capture (UNPROCESSED, MediaRecorder AudioSource) · chirp beacon (master)
  heartbeat (keep-alive against Funtouch's background killer) · transport (TCP/WSS)

PHONE A ALSO RUNS  (because the Snapdragon NPU is the only one available)
  ASR (QNN-exported IndicWhisper / IndicConformer) · TTS readback (Piper)
